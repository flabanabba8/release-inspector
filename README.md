# Release Inspector

Review a selected current source tree with the declared `detect-secrets` scanner and supplementary patterns for credential/configuration names, private IP addresses and some private hostnames. The output includes locations and categories, not matched values; detected sensitive filenames are hidden. Source scans use bounded private snapshots and flag files or directories that change during inspection. A separate bounded ZIP/APK scan examines member names and UTF-8 content, including nested ZIPs up to a limited depth, without extracting by member paths. Binary, encrypted, large or non-UTF-8 members and symlinks are explicitly listed as omissions. Review every indicator and omission; false positives are expected.

For a separately selected binary up to 32 MiB, inspect literal printable ASCII and UTF-16LE strings without returning their values. Findings include byte offsets and encoding; extraction limits and skipped strings are reported. This is partial triage only: short, non-ASCII, compressed, encrypted, fragmented and image text can be missed. ZIP/APK members are not recursively sent to this tool automatically.

The Desktop page offers each inspection mode, including binary-string triage. Functional Desktop and API tests pass; native visual review is still required.

**This prototype cannot certify a release as safe.** A separate bounded Git mode scans reachable UTF-8 blobs, commits and annotated tags from local refs and HEAD, returning object IDs rather than matched values. It rejects shallow repositories and reports omitted binary/tree objects and size limits. It also scans individual UTF-8 Git tree entry names, while reporting unsupported names, submodule histories and Git LFS payloads as omissions. It reconstructs bounded relative Git paths from reachable trees, reporting truncation or missing paths as omissions. It does not fully inspect remote refs, screenshots, binary package content, release assets, all private hostnames or every personal configuration pattern. It does not replace manual inspection, a full secret scan of every exposed revision and artifact, or post-publication verification. The inline allowlist filter is disabled; other scanner filters and heuristics can still miss secrets. Run it only on a narrowly selected directory; paths and line numbers may themselves be sensitive. Scanner output stays in memory and values are not returned. Synthetic fixture tests include credentials removed from a working tree, placed in annotated tags and a directly referenced blob, and nested inside an APK-like archive. Temporary private staging files are cleaned on normal completion; an interrupted process can leave them behind. No complete public-release audit has been performed by this plugin.

Selected artifacts inside the active profile plugin-data directory require explicit `allow_profile_data`; unrelated profile configuration remains blocked. Temporary snapshots are created outside the inspected tree and are cleaned on normal completion. Tests cover private paths, sensitive filenames, changed sources, bounded scanner output, Git objects and nested ZIP/APK content.
